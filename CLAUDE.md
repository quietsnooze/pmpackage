# CLAUDE.md — AI Assistant Guide for pmpackage

## Overview

`pmpackage` is a personal R utility package providing helper functions for:

- **ELO rating systems** (sports/tennis match prediction and simulation)
- **Tennis data fetching** (downloading historical WTA/ATP results)
- **Binary classification modelling** (information value, scorecards, Gini)
- **Data quality checking**
- **ggplot2 theming**
- **GitHub git wrappers**

It follows standard R package conventions (roxygen2 docs, `DESCRIPTION`, `NAMESPACE`).

## Module Details

### ELO System (`R/eloFunctions.R`)

The ELO system uses `collections::dict()` as in-memory hash maps (not R named lists or environments) for performance.

**Typical workflow:**
```r
# 1. Initialise databases
res <- pm_eloPrepDatabase(unseenDataPlayers = c('alice', 'bob'))
eloDB   <- res$eloDB
matchDB <- res$matchDB

# 2. Run ELO across time slices (one date at a time)
res2 <- pm_eloRunMultipleTimeSlices(eloDB, matchDB, eloDF)

# 3. Get ratings at a snapshot date
pm_eloReportElosAtDateFromDatabase(res2$simAllRes, snapshotDate = as.Date('2015-01-01'))
```

**Key data requirements for ELO dataframes:**
- Must have columns: `player_name`, `opponent_name`, `match_date`, `actualResult` (1=player won, 0=player lost)
- `pm_eloRunTimeSlice` treats all rows within a time slice as happening simultaneously (parallel, no ELO update within slice)
- ELO K-factor uses a tennis-specific decay formula: `K = Cfactor / (matches + Coffset)^Cshape`

**Default ELO parameters:** `Cfactor=250`, `Coffset=5`, `Cshape=0.4`, default starting score `1500`

**Known bug:** `pm_eloExtractDatabaseFromDataframe` has a typo at line 99 — `both$plalyer_name` should be `both$player_name`. This function may not work correctly.

**Tournament simulation:** `pm_eloRunTourneyELO` is recursive; `pm_eloSimulateTournamentInParallel` saves results to `.rda` files named `sim_<tournamentName>.rda` in the working directory.

### Tennis Data (`R/tennisFunctions.R`)

- Data sourced from `http://www.tennis-data.co.uk/` — WTA 2007–2018, ATP 2001–2018
- `pm_tennis_fetchDataset(year, competition='WTA')` downloads a single year's Excel file to a temp file
- `pm_tennis_fetchAllDatasets(competition='WTA')` fetches all available years and combines them
- `pm_tennis_eloify_dataset()` converts winner/loser format to player/opponent format with `actualResult`, randomly assigning which side is "player" via `rbinom(..., 0.5)`
- Match dates are adjusted by `+ 1000 * 1/roundNum` to create unique timestamps per round (a deliberate hack to avoid date ties between rounds)

---

### Modelling (`R/modellingFunctions.R`)

**Information Value (IV):**
- `pm_modelling_iv(dv, iv)` computes WoE and IV for a single variable
- `pm_modelling_report_all_info_vals(df, dependent_var)` runs IV for all columns; returns ranked tibble

**Gini / AUC:**
- `pm_modelling_calc_gini(df, predvar, truevar)` returns AUC and Gini coefficient
- Auto-corrects for negatively correlated predictions (flips sign)

**Scorecard:**
- `pm_modelling_build_scard_from_model(mymodel)` — expects a `glm` model fitted with WoE-transformed variables; uses `broom::tidy()`
- `pm_modelling_score_dataframe(df, scorecard)` — applies scorecard to score new data

**Auto-classification:**
- `pm_modelling_autoclass_var()` uses `rpart` to find optimal quantile splits
- `pm_modelling_full_autoclass_var()` adds both autoclassed and WoE-transformed columns to a dataframe

**Player/opponent helpers:**
- `pm_modelling_compare_player_opponent(df, varname)` — creates ratio, difference, log-ratio columns
- `pm_modelling_tidify_player_opponent_dataframe()` — flattens player+opponent rows into single-player tidy format (inverts ratios/differences for the opponent side)
- `pm_modelling_lifetime_performance()` — computes cumulative win/loss rates per player before each match (avoids data leakage via `cumsum - current`)

---

### Data Quality (`R/dataquality.R`)

- `pm_dq_checkColumn(df, colname)` — returns stats (count, missing, infinite, mean, min, max) for one column
- `pm_dq_check_all_columns(df)` — runs the above for every column, returns a summary dataframe
- Note: uses deprecated `select_()` — will produce warnings in modern dplyr

---

### ggplot Theme (`R/ggplotFunctions.R`)

- `pm_ggplot_theme()` — extends `theme_bw` with dashed horizontal gridlines, removes vertical gridlines
- Uses Avenir font (`base_family="Avenir"`) — may need to be changed on systems without Avenir installed

---

### GitHub Wrappers (`R/githubFunctions.R`)

Simple `system()` wrappers — not for programmatic use:
- `pm_gh_config(username, email)` — sets global git config
- `pm_gh_pull_request()` — runs `git pull origin master`
- `pm_gh_push_request()` — runs `git push -u origin master`

## Development Workflow

### Building and installing

```r
# Install dependencies first
install.packages(c('tidyverse','magrittr','data.table','doParallel','foreach',
                   'stringr','ggplot2','Hmisc','lubridate','tibble','readxl',
                   'janitor','purrr','rlang','patchwork','rpart','collections'))

# Install package from source (from within R, project root)
devtools::install()

# Or build and check
devtools::build()
devtools::check()
```

### Regenerating documentation

The `NAMESPACE` and `man/*.Rd` files are auto-generated by roxygen2. **Never edit them manually.**

```r
devtools::document()
```

### Adding new functions

1. Add the function to the appropriate `R/*.R` file (or create a new one)
2. Add roxygen2 `#'` comments above the function with `@param`, `@return`, `@export`, and `@importFrom` tags
3. Run `devtools::document()` to regenerate `NAMESPACE` and `man/`
4. Add any new package dependencies to `DESCRIPTION` Imports section and call `usethis::use_package('pkgname')`

### Note on `usethis::use_package()` calls at top of files

Several R files contain bare `usethis::use_package(...)` calls at the top (e.g. `eloFunctions.R`, `tennisFunctions.R`). These are **development-time setup commands**, not runtime code. They should not be inside functions and should ideally be removed or moved to a setup script — but they are harmless when the package is installed (they're just ignored at runtime).

## Known Issues and Technical Debt

1. **Typo in `pm_eloExtractDatabaseFromDataframe`** (`R/eloFunctions.R:99`): `both$plalyer_name` should be `both$player_name`. This function is likely broken.
2. **Deprecated dplyr NSE functions**: `select_()`, `group_by_()`, `arrange()` without `dplyr::` prefix in some places — these use old underscore-suffix NSE API removed in dplyr 1.0.
3. **`as.tibble()` deprecated**: Should be `tibble::as_tibble()` in newer tibble versions.
4. **`pm_eloOptimiseKfactor`**: The `optim()`-based code is commented out; the current implementation is a brute-force grid search.
5. **Tennis data URLs**: Hardcoded to 2007–2018 WTA and 2001–2018 ATP. Data beyond 2018 is not available through these paths.
6. **`pm_modelling_build_scard_from_model`** depends on `broom` package which is not listed in `DESCRIPTION`.
7. **`pm_modelling_score_dataframe`** uses `tidyr::gather()` which is superseded by `tidyr::pivot_longer()`.
8. **`grid` package** used in `pm_modelling_plot_variable` but not listed in `DESCRIPTION`.

## Data Conventions

- Match result encoding: `actualResult = 1` means the `player_name` won; `actualResult = 0` means the `opponent_name` won
- ELO columns added by the system are always prefixed with `elo_`
- Player-side columns are prefixed with `player_`; opponent-side columns with `opponent_`
- Dates are `Date` class objects (not POSIXct) throughout the ELO pipeline
- The `collections::dict()` object is a mutable reference — ELO databases are updated in-place within loops
